# progress-panel 0.2 仕様書：利用枠・コンテキストメーター

## 目的

goal2 で長い作業を任せたり、サブエージェントを何体も同時に動かしたりすると、気づかないうちに利用枠やコンテキストを使い切りがちです。その手前で気づけるよう、今の progress-panel に次の機能を足します。

- 画面下のステータス行に、利用枠とコンテキストの使用率を常に出す
- 決まった段階を超えたときに一度だけ知らせる
- 消費のペースが早いときは、その状態のあいだ表示し続ける

新しい mod は作らず、progress-panel を拡張します。ステータス行は1つの mod につき1本までなので、既存の「作業中 1/3・…」の行に続けて出します。

## データの出どころ

| 値 | 取り方 |
| --- | --- |
| 利用枠（`five_hour`、`seven_day`、ほか） | `session.measure` イベントの `rateLimits`（`percentUsed`、`resetsAt`） |
| コンテキスト | `session.measure` の `context.percent`（モデルのコンテキスト長に対する割合）と `tokens`・`window` |
| 起動直後の値 | `session.start` で `$.session.usage()` を一度読む |

前提と制約：

- 利用枠の数値は「このセッションが最後に受け取った API 応答」時点のものです。ほかのセッションや claude.ai で使った分は、次の応答まで反映されません。そのためパネルには、値を取得した時刻を出します。
- サブスクリプション以外（API キーなど）では `rateLimits` が空になります。その場合、利用枠の表示は丸ごと省きます。
- `/compact` の直後は、次の応答まで `context.percent` がありません。値が届かないあいだは、直前の値を残さず「—」とします。
- `session.measure` が呼ばれるのは、メインスレッドのターンが終わったときと、利用枠が1ポイント動いたときです。

## ステータス行

既存の要約の後ろに ` ｜ ` で区切ってつなげます。

```
作業中 1/3・コマンドを実行中 ｜ 5時間 62%（18:40 回復）・週 35%・文脈 45%▲
```

- **5時間枠**：`5時間 NN%（HH:MM 回復）`
  - 80%以上なら先頭に `⚠` を付けます。
  - ペースが早いときは `（18:40 回復・17:55頃に上限）` のように、上限に達する予測時刻を添えます。
  - 回復時刻を過ぎていれば `5時間 回復済み` と出します（次の応答で更新されます）。
- **週枠**：`週 NN%`
  - 80%以上なら `⚠` を付け、`（10/22 回復）` のように回復日を添えます。
  - ペースが早いときは `（ペース速め）` を添えます。
- **知らない種類の枠**（ゲートウェイの `spend_limit` など）：`kind NN%` と汎用の形で出します。
- **コンテキスト**：`文脈 NN%`
  - 40%以上で `▲`、50%以上で `⚠`、60%以上で `‼` を付けます。
- 利用枠もコンテキストも値がなければ、区切りごと出しません（今の表示のままになります）。

## 通知（トースト）

| きっかけ | 文面の例 | 表示時間 | 重複の防ぎ方 |
| --- | --- | --- | --- |
| 利用枠が80%を超えた | 5時間枠が81%になりました。18:40 に回復します。 | 8秒 | 枠ごと・回復時刻ごとに1回（`$.store`） |
| 利用枠が95%を超えた | 5時間枠が96%です。まもなく上限です（18:40 回復）。 | 20秒 | 同上 |
| ペースが「速め」に変わった | 5時間枠の消費ペースが速めです。このままだと17:55頃に上限です。 | 10秒 | 同上 |
| コンテキストが40%を超えた | 文脈が40%を超えました。 | 6秒 | 段階ごとに1回（`$.state`） |
| コンテキストが50%を超えた | 文脈が50%を超えました。/compact か /clear を検討する頃合いです。 | 10秒 | 同上 |
| コンテキストが60%を超えた | 文脈が60%を超えました。区切りのよいところで /compact か /clear をおすすめします。 | 15秒 | 同上 |

- **95% のときの OS 通知**：トーストに加えて、`$.ui.notify` で OS の通知も送ります。ただしデスクトップアプリでは OS 通知を送れない（`no-surface` が返る）仕様なので、届くのはターミナルで使っている場合だけです。デスクトップアプリでは、長めのトーストと、ステータス行の `⚠` で代わりにします。
- **利用枠の通知済み記録**：`$.store` に枠の種類ごとに `{ resetsAt, level, isFastNotified }` として保存します。セッションをまたいで残り、mod を再読み込みしても消えません。`resetsAt` が変わったら（＝枠が回復したら）記録をリセットします。回復時刻は応答ごとに数秒ずれることがあるので、差が10分未満なら同じ枠とみなします（0.4.0 は10分単位に丸めて比べていたため、境目の前後で同じ枠が別の枠に見えることがありました）。回復時刻のない枠（ゲートウェイの `spend_limit` など）は、通知した段階より5ポイント以上下がったら、また通知できる状態に戻します。
- **一度に複数の段階を越えたとき**：通知は、越えたうちのいちばん上の段階について1回だけ出します。たとえば一度に 70%→96% になったら、95% の通知だけを出します。
- **コンテキストの通知済み記録**：`$.state` に、通知済みのいちばん上の段階を保存します。`/compact` などで使用率がその段階より5ポイント以上下がったら、現在の値より上の段階をまた通知できる状態に戻します。

## ペース判定

- **5時間枠**：直近30分のサンプル（取得時刻と使用率の組）から傾きを求め、100%に達する予測時刻を出します。
  - 判定に使えるのは、同じ回復時刻のサンプルが2つ以上あり、最初と最後が10分以上離れていて、そのあいだに2ポイント以上増えている場合だけです。
  - **速めになる条件**：予測時刻が回復時刻より10分以上前のとき。
  - **戻る条件**：予測時刻が回復時刻以降になったとき、または判定に使えるサンプルがなくなったとき。差をつけてあるのは、表示がちらつかないようにするためです（ヒステリシス）。
- **週枠**：直近の傾きで判定すると、作業が集中した時間帯にばかり反応してしまいます。そのため枠の始まりからの平均で判定します。
  - 計算式：経過割合 ＝ 1 −（回復までの残り時間 ÷ 7日）
  - **判定する条件**：経過割合が 0.1 以上で、使用率が20%以上のとき。
  - **速めになる条件**：使用率 ÷ 経過割合 が 110% 以上（このまま回復時刻まで続くと上限を超える見込み）。
  - **戻る条件**：100% 未満になったとき。
- **そのほかの枠**：ペース判定はしません。
- **サンプルの保存先**：`$.state`（セッション内）。枠ごとに直近の最大60件まで持ちます。利用枠の使用率はアカウント全体の値なので、どのセッションで集めても結果は同じです。

## パネル

上から次の順に並べます。中身のない項目は出しません。

1. いまの状態（既存のまま）
2. **利用枠**
   ```
   利用枠（18:02 時点）
   5時間 62% ■■■■■■□□□□ 18:40 回復
     ⚠ ペース速め：このままだと 17:55 頃に上限
   週   35% ■■■■□□□□□□ 10/22 回復
   ```
3. **コンテキスト**
   ```
   コンテキスト 45% ■■■■□□□□□□
   約 90k / 200k トークン・次の目安 50%
   1ターンあたり約 +3%・あと 2 ターンほどで 50%
   ```
   - 「1ターンあたり」の増え方は、直近5ターンの平均です。ターンはメインのターンが終わった回数で数えるので、使用率が動かなかったターン（計測が届かないターン）も1ターンとして数えます。ターンの途中の計測（利用枠が動いたときなど）は、そのターンの値として上書きします。増えていないときは出しません。
4. **サブエージェント**（0.3 で追加。後述）
5. **作業ログ**（0.3 で追加。後述）
6. やることリスト（中身があるときだけ出します。今の「まだありません」の行はなくします）

## 第2段階（0.3）：サブエージェント一覧と作業ログ

### サブエージェント一覧

- **取り方**
  - 起動：`agent.spawn` で `next(e)` が返した `agentId` と、`description`（作業の短い説明）・`subagentType`（種類）・起動時刻を記録します。起動が拒否されたものは記録しません。
  - 終了：そのサブエージェントの `turn.complete`（`agentId` 付き）で終了時刻を記録します。SendMessage で再開されて `turn.start` が来たら、実行中に戻します。
- **パネル**：実行中または完了したものがあるときだけ出します。
  ```
  サブエージェント（実行中 3）
  ▶ Explore：認証まわりを調査 1分20秒
  ✓ worker：テストを修正 2分5秒
  ```
- **完了したものの片付け**：メインの次のターンが始まったら一覧から消します。実行中のものは残します。保持するのは最大20件です。
- **ステータス行**：実行中のものがあるときだけ、要約に `・サブ 3` を足します。
  例：`作業中 1/3・手分けして作業中・サブ 3 ｜ 5時間 …`
- **バックグラウンドで動くサブエージェント**：終了したときに `turn.complete` が来るので、メインが待機中でも完了の印が付きます。ただし経過時間の表示は、メインが作業中のあいだしか毎秒は更新されません。

### 作業ログ

`tool.call` の結果を見て、次のものを時系列で記録します。サブエージェントのツール呼び出しも記録し、その場合は誰の操作かがわかるように印を付けます。

| 種類 | 拾い方 | 記録する内容 |
| --- | --- | --- |
| 編集 | Edit・Write・NotebookEdit が成功したとき | ファイルパス、回数。同じファイルへの連続した編集は1行にまとめます（`×6`） |
| テスト | Bash・PowerShell のコマンドが、テストのパターン（`npm test`、`pytest`、`vitest`、`jest`、`cargo test`、`go test`、`claude plugin test` など）に合ったとき。`&&`・`;`・`|` で区切った各コマンドの**先頭**で見分けます（`npx`・`uv run`・`FOO=1` などの前置きは飛ばします）。`rg pytest`（検索）や `cat jest.config.js`、`git commit -m "…test"` はテストに数えません | コマンド、結果 |
| チェック | 型チェックや lint のパターン（`tsc`、`eslint`、`ruff`、`mypy`、`claude plugin validate` など）に合ったとき。見分け方はテストと同じです | コマンド、結果 |
| コミット | `git commit` を含むコマンドが成功し、出力に `[ブランチ ハッシュ] 件名` があったとき。出力がないとき（`git commit -q`）は、そのコミットをした場所の HEAD を git に聞きます（下の「静かなコミット」） | ハッシュ、件名 |

- **結果の見分け方**
  - 成功：`isError` なし
  - 失敗：`isError` あり（終了コードが 0 以外）
  - 中断：`interrupted`。中断されたツールはエラーとして返り、結果は文字列だけになるので、Claude Code の中断の知らせ（`[Request interrupted by user`）で始まるときも中断とします
  - 結果が空のまま失敗したときも、失敗として記録します
  - バックグラウンド実行：`backgroundTaskId` あり（結果は記録できないので「バックグラウンド」とだけ残します）
- **伏せ字**：コマンドは1行目だけを最大80文字まで記録し、次のものを `***` に置き換えます。
  - `token=…`・`password=…` のような値と、`--password hunter2`・`--token abc` のように空白のあとに続く値
  - URL の中のユーザー名とパスワード（`https://alice:pw@…` → `https://***@…`）、`Authorization:` ヘッダーの値（方式名は残します）、`curl -u user:pass`
  - `sk-…`・`ghp_…`・`glpat-…`・`AKIA…`・`AIza…` のようなトークン
  - 32文字以上の英数字の並び。英数字以外も混じる並びは、数字と英字の両方を含むときだけ伏せます。パス（`/` を含む）や `test_payment_gateway_flow` のような名前は伏せないので、別のテストが同じ `pytest ***` にまとまることはありません
- **コミット**：`[detached HEAD abc1234] …`（rebase 中など、ブランチの外のコミット）も読み取ります
- **静かなコミット**：`git commit -q` は何も出力しないので、`git log -1 --format=%h%x09%ct%x09%s` で HEAD のハッシュ・時刻・件名を読みます（0.5.2 から）。
  - 場所は、コマンドの `git -C <フォルダ>` から読みます。なければ、`git commit` より前の最後の `cd`（`Set-Location`・`pushd` も）から読みます。どちらもなければ、セッションのフォルダです。Git Bash の `/c/…` は `C:/…` に直します
  - 10分以内のコミットで、作業ログにまだないものだけを記録します。`git commit -q …; echo done` のように、コミットが失敗しても成功で終わるコマンドで、前からある HEAD を新しいコミットと取り違えないためです
  - 前のコマンドの `cd` を引き継ぐシェルで、コマンドに `cd` が書かれていないときは、場所を読み違えることがあります。たいていは時刻か重複の条件で外れて記録されないだけですが、セッションのフォルダでも10分以内に別のコミットがあれば、それを拾うことがあります
- **保持**：`$.state` に最大200件まで持ちます（mod を再読み込みしても残ります）。
- **パネル**：直近5件を、新しいものが下にくる順で出します。全件は `/worklog` で見られます。
  ```
  作業ログ（全 23 件・/worklog で全件）
  15:02 編集 register.tsx ×6
  15:10 ✗ テスト claude plugin test .
  15:12 ✓ テスト claude plugin test .
  15:20 コミット 6c6bb45 Add usage and context meter
  ```
- **/worklog**：引き継ぎメモの下書きになる Markdown を返します。返した内容は Claude も読めるので、そのまま handoff スキルの材料にできます。中身は次の順です。
  1. 時系列（全件）
  2. 変更したファイルの一覧（重複を除いたもの）
  3. テスト・チェックの、コマンドごとの最後の結果
  4. コミットの一覧
  5. 注意書き：シェルコマンドによる変更や、ユーザー自身の編集は含まれないこと
- **取りこぼすもの**（仕様上の限界）
  - `sed` などのシェルコマンドで書き換えたファイル
  - ユーザー自身の編集
  - バックグラウンドで実行したテストの結果

## 第3段階（0.4）：区切りどきの知らせと、自動圧縮前の最後の警告

40%・50%・60% の知らせは、% だけで出ます。そのため作業の途中でも出てしまい、切りの悪いところで区切ることになりかねません。0.4 では、% と作業の区切りを組み合わせた知らせと、自動圧縮が近いときの最後の警告を足します。圧縮やクリアを自動ですることはありません。決めるのは人です。

### 区切りどきの知らせ

メインのターンが終わったときに、次の2つがそろっていればトーストで知らせます。

1. コンテキストが 50% 以上
2. そのターンで、作業が区切りに来た。区切りとみなすのは次のどれかです。
   - やることリストがあり、全部完了した
   - コミットした
   - 前に失敗していたテスト・チェックが成功した

文面の例：

> 区切りどきです（文脈 55%）。/handoff で引き継ぎメモを作り、新しい会話へ移るのがおすすめです。

- 区切りでは、`/compact` より `/handoff`（引き継ぎメモを作るスキル）で新しい会話へ移るよう誘います（0.5.3 から）。圧縮の要約は2万〜6万トークンあって中身が見えませんが、引き継ぎメモは数千トークンで、ファイルとして読めて直せるからです。作業の途中の知らせ（50%・60%、自動圧縮前の最後の警告）は、そのまま `/compact` をすすめます。途中では引き継ぎメモを書く区切りがないからです。
- 一度知らせたら、使用率がさらに 10 ポイント増えるまでは、区切りが来ても知らせません。何度も出てうるさくならないようにするためです。
- `/compact` などで使用率が 50% 未満に下がったら、また知らせられる状態に戻します。
- 50% を超えていても作業の途中なら、知らせません（ステータス行の `⚠` などの印だけです）。

### 自動圧縮前の最後の警告

- **自動圧縮が始まる位置（圧縮の基準値）の取り方**：`$.session.usage({ breakdown: 'summary' })` が返す `autoCompactThreshold`（自動圧縮が動くトークン数）を使います。これがない版では `rawMaxTokens`（測る対象の窓の大きさ）で代えます。`isAutoCompactEnabled` が false（自動圧縮が切ってある）なら、最後の警告もパネルの基準の行も出しません。これはローカルで見積もる呼び出しで、API は呼びません。呼ぶのは使用率が 50% 以上になってからで、結果は保存して使い回します。`/model` でコンテキストの窓の大きさが変わったら、その窓について読み直します。
- **警告の条件**：使用中のトークン数が、圧縮の基準値の 90% を超えたら、区切りかどうかに関係なく一度だけ知らせます。

  > まもなく自動で圧縮されます（基準の 91%）。区切りのよいところで /compact をおすすめします。

- **パネル**：コンテキストの項目に「自動圧縮の基準 約 NNNk まで あと NNk」の行を足します。
- **確かめたこと**：0.4.0 は `rawMaxTokens` を使っていましたが、型定義ではこれは「測る対象の窓の大きさ」で、自動圧縮はその手前の `autoCompactThreshold` で動きます。そのため 200k のモデルでは、警告（180k）より先に圧縮（約 167k）が起きていました。0.4.1 で基準を `autoCompactThreshold` に直しました。90% という値が適切かは、引き続き compact-memo の記録で見直します。

## 第4段階（0.5）：ほかのセッションの一覧

### 目的

デスクトップアプリで、作業ごとに worktree を分けて複数のセッションを同時に動かすことがあります。どのセッションが作業中で、何をしていて、やることリストのどこまで進んだかを、セッションを切り替えずに1つのパネルで見られるようにします。

新しい mod は作りません。セッションの進み具合はそのセッションの中（`$.state`）にしかなく、別の mod からは読めないためです。進み具合を集めている progress-panel が、自分の状況を共有の場所に書き出し、ほかのセッションの分を読んで表示します。

### しくみ

- **共有の場所**：`$.store`（`~/.claude/plugins/store/` の下にある、この mod 専用の JSON ファイル）。同じマシンで progress-panel を読み込んでいるすべてのセッションから読み書きできます。
- **1セッション1項目**：キーは `session:<セッションID>`。各セッションは自分のキーだけを書き換えます。
- **同時に書いても消えないこと**：2つのセッションが同時に 20 件ずつ書き込んでも 40 件すべてが残り、互いの書き込みを読めることを、実際のエンジン2つで確かめました（2026-10-19）。`$.store` はキーごとにファイルへ反映されます。
- **変化の知らせはない**：ほかのセッションが書いたことを知る仕組みはないため、一定の間隔で読み直します。表示は最大で読み直しの間隔ぶん遅れます。

### 書き出す内容

| 項目 | 内容 |
| --- | --- |
| `id` | セッションID（`$.session.id()`） |
| `folder` | プロジェクトのフォルダの名前（`$.session.root()` のパスの最後の部分。worktree なら `claude-mods-session-board` など）。`$.session.cwd()` はフックの中ではサブエージェント自身のフォルダを返し、シェルの `cd` でも動くので使いません |
| `branch` | git のブランチ名。git の外なら空。ブランチの外のコミット（rebase の途中、detached HEAD）では `ブランチ外 abc1234` |
| `request` | ユーザーの最新の依頼の1行目。最大 40 文字。作業ログと同じ伏せ字をかけます |
| `isWorking`・`action` | 作業中かどうかと、いま何をしているか（パネル上段と同じもの） |
| `done`・`total` | やることリストの完了数と全体の数 |
| `current` | 取り組み中のやることの名前。なければ空 |
| `context` | コンテキストの使用率（%）。まだ届いていなければなし |
| `updatedAt` | 書き出した時刻。生存の合図でも進みます。「応答なし」と片付けの判定にだけ使います |
| `activeAt` | 最後に動いた時刻：作業中ならそのターンの始まり、待機中なら最後のターンの終わり。まだ一度も動いていなければ書き出しを始めた時刻。「待機中・N分前」と並び順に使います（0.5.1 で追加。0.5.0 の項目にはないので、そのときは `updatedAt` で代えます） |

- **書き出すとき**：セッションの開始、ユーザーの依頼、メインのターンの開始と終わり、やることリストやいまの操作が変わったとき、コンテキストの計測が届いたとき。ツールを使うたびに書くと多すぎるので、続けて変わったときは **5 秒に1回** にまとめます（最後の状態は必ず書きます）。
- **生存の合図**：何も変わらなくても **60 秒ごと** に書き直します（`updatedAt` を進めます）。待機中のセッションも合図を出し続けます。
- **ブランチ**：最初に書き出すときと、メインのターンが終わるたびに `git rev-parse --abbrev-ref HEAD` をプロジェクトのフォルダで実行して読みます（3 秒で打ち切り）。待つのはセッションの開始時の1回だけで、ターンの終わりは git の答えを待たずに終わり、読めた時点で書き出し直します。打ち切りや一時的な失敗のときは、前に読めたブランチ名を残します（git の外だと分かったときだけ空にします）。ターンの途中で `git checkout` しても、そのターンの終わりに反映されます。
- **終わるとき**：`session.end` で自分のキーを消します。`/clear` と `/resume` ではセッションIDが変わり、`session.start` も来ないので、古いIDのキーを消し、以後は新しいIDで書き続けます。それ以外の終わり方では、書き出しも読み直しも止めます。終わりの合図は、ほかの処理を待つ前に立てます。そのため、終わりと同時に書き込みが進んでいても、消したキーが書き戻されて「応答なし」で残ることはありません（書き戻されてしまったら、すぐ消し直します）。
- **始まるとき**：生存の合図と読み直しのタイマーを先に作り、それから最初の書き出しと読み直しをします。最初の書き込みが一度失敗しても（Windows でファイルが一瞬使用中だった、など）、次の合図で書き出せます。
- **書き出すセッション**：ターミナルの対話セッションと、画面（surface）のつながったセッションです。デスクトップアプリのセッションは SDK 経由で動くため `isInteractive` は false ですが、アプリが描画を始めた時点（`$.session.surfaces()` が空でなくなった時点）から書き出します。画面のない `claude -p` は書き出しません。サブエージェントは別のセッションではないので、一覧には出ません（親のセッションの行の「手分けして作業中」で分かります）。

### 表示

- **読み直し**：**10 秒ごと** と、セッションの開始時に読みます。自分のキーは除きます。内容が変わったときだけパネルを描き直します。
- **パネル**：作業ログの下、やることリストの上に「ほかのセッション」の項目を足します。ほかのセッションがないときは出しません。
  ```
  ほかのセッション（作業中 2・待機 1）
  ● claude-mods-session-board（add-session-board）
    作業中 2/5・コマンドを実行中・文脈 45%
    ▶ テストを書く
  ○ second-brain（main）
    待機中 3/3・4分前
    依頼：週次レポートを作って
  ? claude-mods（main）応答なし・12分前
  ```
  - 1行目：印、フォルダ名、ブランチ名。印は `●` 作業中、`○` 待機中、`?` 応答なし。
  - 2行目：状態、やることの進み（あれば）、いまの操作（作業中のとき）、文脈（あれば）、待機中なら最後に動いてからの時間。
  - 3行目：取り組み中のやることがあればそれを `▶` 付きで、なければ依頼の1行目を出します。どちらもなければ出しません。
  - 並び順：作業中、待機中、応答なしの順。同じ中では最後に動いたもの（`activeAt`）が新しい順です。生存の合図の時刻では並べないので、待機中のセッションが1分ごとに入れ替わることはありません。
  - スマホなど外からつないだ画面（Remote Control）では、件数の見出しだけを出し、ほかのセッションの依頼・やること・フォルダ名は出しません。このパソコンの画面（ターミナル・デスクトップアプリ）では全部出します。
  - 最大 6 セッションまで出し、残りは「ほか N 件」とまとめます。
- **応答なし**：最後の書き出しから **3 分**（合図3回分）たったセッションは「応答なし」にして薄く出します。アプリを閉じた、PC がスリープした、などでセッションが合図を出せなくなった場合です。
- **片付け**：最後の書き出しから **30 分** たったキーは、読み直したセッションが消します。スリープから戻ったセッションは、次の合図でまた現れます。この版が読めない形のもの（ほかの版の項目）は、書き出した時刻が読めれば同じく 30 分で消し、読めなければ残します。オブジェクトでない値は、どの版の項目でもないので消します。
- **ステータス行**：ほかに作業中か待機中のセッションがあれば、自分の要約のあとに ` ｜ 他 作業中2 待機1` を足します（応答なしは数えません）。

### 前提と限界

- 一覧に出るのは、progress-panel 0.5 以降を読み込んでいる Claude Code のセッションだけです。mod を入れていないセッション、Codex、ほかのマシンのセッションは出ません。
- 表示は最大 10 秒（ほかのセッションの書き出しの間引きを含めると 15 秒ほど）遅れます。
- 依頼の1行目、取り組み中のやることの名前、フォルダ名、ブランチ名が、ローカルの JSON ファイルに平文で残ります。依頼とやることには、作業ログと同じ伏せ字に加えて、「パスワードは hunter2」「token: abc」のように言葉で書いた秘密の値も伏せます。依頼の1行目は、取り消された依頼や、文字のない依頼（画像だけなど）では書き換えません。40 文字で切るときは、絵文字などを途中で切りません。
- VS Code 拡張のセッションは画面（surface）がつながらないため、一覧に出ません。
- デスクトップアプリのセッションのタイトルは mod から読めないため、代わりに依頼の1行目を出します。
- コンテキストにも利用枠にも影響しません（Claude には何も渡さず、モデルも呼びません）。

## 0.4.1：検証で見つかった問題の修正

0.4.0 を検証して見つかった問題を直しました。上の各節も、直したあとの動きに書き換えてあります。

- **自動圧縮前の最後の警告**：基準を `autoCompactThreshold` にしました。自動圧縮が切ってあるときは警告しません。`/model` で窓が変わったら基準を読み直します。
- **区切りどきの誤った知らせ**：テスト・チェックをコマンドの先頭で見分けるようにしました。伏せ字でパスが潰れて別のテストが同じものに見えることも、中断が失敗に数えられることも、直しました。
- **区切りどきの判定の時機**：ターンの終わりに区切りでも使用率がまだ届いていないときは、そのターンの計測が届いた時点で判定します（区切りを覚えておき、次のターンが始まったら忘れます）。
- **書き込みの取りこぼし**：計測の反映と区切りどきの記録を、書き込む時点の値をもとに計算するようにしました。同時に動いても、通知済みの記録が消えません。
- **ペース判定と通知の重複**：回復時刻の数秒のずれを同じ枠とみなすようにしました。
- **伏せ字**：URL の中のパスワード、`Authorization` ヘッダー、空白区切りの値、GitLab・AWS・Google のキーを伏せるようにしました。
- **表示**：`/compact` のあとに「文脈 —」と出します。時刻を `09:05` のように2桁で出します。待機中に回復時刻を過ぎたら、次の出来事を待たずに「回復済み」に変えます（1日以内の回復時刻だけを待ちます）。ペースのパネル表示に `⚠` を付けました。
- **1ターンあたりの増え方**：ターンの回数で割るようにしました（動かなかったターンも数えます）。

## 0.5.1：ほかのセッションの一覧の修正

0.5.0 を検証して見つかった問題を直しました。上の 0.5 の節も、直したあとの動きに書き換えてあります。

- **待機中の「N分前」**：生存の合図とは別に、最後に動いた時刻（`activeAt`）を書き出し、それで「待機中・N分前」と並び順を決めます。これまでは合図のたびに時刻が進み、何分待機しても「たった今」でした。
- **`/resume` のあと**：`/clear` と同じく、新しいIDで書き出しと読み直しを続けます。これまでは止まってしまい、そのウィンドウが一覧から消えていました。
- **最初の書き込みの失敗**：タイマーを先に作るので、最初の1回が失敗しても次の合図で書き出せます。
- **フォルダ名とブランチ名**：`$.session.root()`（プロジェクトのフォルダ）から読みます。サブエージェントやシェルの `cd` でぶれません。
- **終わりと書き込みの重なり**：終わったセッションの項目が書き戻されて「応答なし」で残ることがなくなりました。`/clear` のあとに自分の古い項目が「ほかのセッション」に出ることもありません。
- **git を待たない**：ターンの終わりは git の答えを待ちません。読み取りに失敗しても前のブランチ名を残し、ブランチの外では `ブランチ外 abc1234` と出します。
- **見せる範囲と伏せ字**：スマホなど外からつないだ画面には、ほかのセッションの中身を出しません。やることの名前も伏せ字にし、言葉で書いた秘密の値も伏せます。
- **そのほか**：ほかの版の項目を消さないようにしました。取り消された依頼や文字のない依頼で依頼文を書き換えません。絵文字を途中で切りません。VS Code 拡張のセッションが出ないことを、前提と限界に書きました。

## 0.5.2：静かなコミットも作業ログに残す

`git commit -q` でしたコミットが、作業ログに載っていませんでした。出力に `[ブランチ ハッシュ] 件名` がないためです。作業ログのコミットは compact-memo の退避メモにも使うので、圧縮のときに「残すことがなかった」となっていました。出力からハッシュを読めないときは、コミットした場所の HEAD を git に聞くようにしました（上の作業ログの節の「静かなコミット」）。

## 0.5.3：区切りどきの知らせで /handoff をすすめる

区切りどきの知らせの文を「続ける前に /compact か /clear を検討してください」から「/handoff で引き継ぎメモを作り、新しい会話へ移るのがおすすめです」に変えました。区切りで圧縮しても、compact-memo の退避メモはほとんど作られず（残す事実がないため）、要約の中身も確かめられなかったからです。知らせる条件と間隔は変えていません。
