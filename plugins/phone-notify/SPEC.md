# phone-notify 仕様書：スマホへの通知

## 目的

goal2 で長い作業を任せて席を外していると、Claude が承認待ちで止まったり、エラーで止まったりしても気づけません。デスクトップアプリでは mod から OS の通知を送れないので、goal2 の一時停止や progress-panel の「利用枠 95%」の通知も届いていません。

この mod は、決めた場面で必ず、ntfy（無料の通知サービス）を通してスマホに通知を送ります。

## 準備（使う人がすること）

1. スマホに ntfy のアプリを入れる（iPhone・Android とも無料）
2. 推測されにくいトピック名（通知の宛先の名前）を決めて、アプリで購読する（例：`arima-claude-7f3k9q`）
3. Claude Code で `/plugin configure phone-notify@claude-mods` を実行し、トピック名を入れる
4. `/phone-notify` を実行して、テスト通知が届くことを確かめる

## 通知する場面

| 場面 | 拾い方 | タイトル | 本文の例 | 優先度 |
| --- | --- | --- | --- | --- |
| 承認待ち | `classic.Notification` のうち `permission_prompt` と `elicitation_dialog` | 【フォルダ名】入力待ち | Claude needs your permission to use Bash（エンジンの文面のまま） | 高 |
| 質問で止まった | `AskUserQuestion` ツールが呼ばれたとき（質問を出すのと同時に送る） | 【フォルダ名】質問があります | 最初の質問の文（120文字まで） | 高 |
| 作業の最後に質問した（デスクトップアプリ） | メインの `mcp__ccd_turn__wrap_up` が `ask` 付きで呼ばれたとき。作業の長さは問いません | 【フォルダ名】質問があります | `ask` の文（120文字まで） | 高 |
| 長い作業が終わった | メインの `turn.complete`。`reason` が `answer` で、かかった時間が設定の分数以上のとき | 【フォルダ名】作業が終わりました | 12分かかりました | 普通 |
| エラーで止まった | メインの `classic.StopFailure` | 【フォルダ名】エラーで止まりました | overloaded（エラーの種類） | 高 |
| ほかの mod の知らせ | `classic.Notification` のうち `plugin_notification`（mod が `$.ui.notify` で出した通知） | 【フォルダ名】（mod が付けた見出し） | mod の文面の最初のコロン（`:`・`：`）か括弧（`（`・`(`）の手前まで。切ったときは「（続きはパソコンで）」を付ける。`modDetail` がオンなら全文 | 高 |
| そのほかの知らせ | `classic.Notification` のうち、上の種類にも下の「通知しないもの」にも入らないもの | 【フォルダ名】お知らせ | エンジンの文面 | 普通 |

- **フォルダ名**：セッションを開いたフォルダの名前です。並行して作業していても、どのセッションの知らせかがわかります。
- **通知しないもの**
  - サブエージェントの動き
  - ユーザーが自分で中断したターン
  - 設定の分数より短い作業の終わり
  - `idle_prompt`（返事を終えて次の入力を待っている状態）。作業の終わりは `turn.complete` で、かかった時間を見て判断します。
  - `auth_success`（ログインの完了）
  - デスクトップアプリで作業の最後に質問したターンの「作業が終わりました」（質問として知らせ済みのため）。途中で `AskUserQuestion` で質問し、答えたあとに作業が続いたターンは、終わりも知らせます。
- **同じ通知を続けて送らない**：タイトルと本文が同じ通知は、60秒以内なら2回目を送りません。同時に2つ出た場合も1つだけ送ります（送る前に記録し、送れなかったら記録を取り消します）。

## 送り方

- ntfy の JSON 形式で、`<サーバー>` に POST します（`$.http.fetch`）。本文は `{ topic, title, message, priority, tags }` です。日本語のタイトルを HTTP ヘッダーに入れると文字化けするので、JSON 形式を使います。
- 本文は 200 文字までに切ります。
- 優先度は、高いものが 4、普通のものが 3 です。tags には絵文字の名前（`hourglass`・`white_check_mark`・`warning`・`bell`）を入れます。
- **待たずに送る**：フックは送信の完了を待ちません。質問の表示、ターンの終わり、エラーの処理は、ntfy の速さにかかわらずすぐに進みます（`/phone-notify` のテスト通知だけは、結果を返すために待ちます）。
- **制限時間**：ntfy が **10 秒** 以内に答えなければ、その通知はあきらめて、送れなかったものとして扱います。
- **送れなかったとき**：セッションごとに最初の1回だけ、トーストで「スマホ通知を送れませんでした（理由）」と知らせます。作業は止めません。

## 文面に入れないもの

- コードやファイルの中身、Claude の返事の本文、コマンドの中身
- 入れるのは、フォルダ名、場面、エンジンや mod が出した短い文、エラーの種類、かかった時間だけです。
- ntfy.sh の公開トピックは、名前を知られると誰でも読めます。トピック名は推測されにくいものにします。気になる場合は、自分のサーバーで ntfy を動かし、設定の `server` を変えます。

## 設定（userConfig）

| 項目 | 内容 | 初期値 |
| --- | --- | --- |
| `topic` | ntfy のトピック名（秘密の値として保存） | 空（未設定のあいだは送らない） |
| `server` | ntfy のサーバー | `https://ntfy.sh` |
| `doneAfterMinutes` | 作業の終わりを知らせる最短時間（分） | 3 |
| `notifyWaiting` | 入力待ち・質問を知らせる | オン |
| `notifyDone` | 作業の終わりを知らせる | オン |
| `notifyError` | エラーを知らせる | オン |
| `notifyMods` | ほかの mod の知らせを転送する | オン |
| `modDetail` | ほかの mod の知らせを全文で送る | オフ |

- `topic` が未設定のときは、セッションの開始時に一度だけトーストで設定方法を知らせます。

## コマンド

- `/phone-notify`：テスト通知を送り、送れたかどうかを返します。トピック名が未設定なら、設定方法を返します。

## 費用

ntfy.sh は無料で使えます。課金が発生する外部 API ではありません。

## テスト

`claude plugin test plugins/phone-notify` で、次の場合を確かめます。

- 承認待ち・質問・長い作業の終わり・エラー・mod の知らせで、決めたタイトルと本文が送られること
- 短い作業の終わり、中断、`idle_prompt`、サブエージェントでは送らないこと
- 同じ通知を60秒以内に続けて送らないこと
- トピック名が未設定なら送らず、トーストで知らせること
- 場面ごとのオン・オフ、サーバーの変更が効くこと
- 送れなかったときに、トーストが一度だけ出ること
- `/phone-notify` のテスト通知
- （0.1.1）`tests/fixes.test.ts`：ntfy が遅くても質問・ターンの終わり・エラーが待たされないこと、10 秒であきらめること、同時に出た同じ通知が1つになること、デスクトップの質問のボックスを知らせること（短い作業でも。長い作業では作業の終わりと重ねない）、途中の質問のあとの長い作業の終わりは知らせること、mod の知らせを最初のコロンや括弧の手前までにすること（`modDetail` なら全文）、通知の種類ごとの扱い

## 0.1.1：検証で見つかった問題の修正

- **送信を待たない**：これまでは送信の完了を待ってから質問を表示していたので、ntfy が遅いと質問の画面が出るのも遅れていました。今は待たずに進め、10 秒で答えがなければあきらめます。
- **デスクトップアプリの質問のボックス**：作業の最後に「次にどうしますか？」と質問したときも知らせます。これまでは、3分より短い作業が質問で終わっても知らせていませんでした。
- **mod の知らせの中身**：ntfy.sh の公開トピックは名前を知られると誰でも読めるため、ほかの mod の知らせは最初のコロンや括弧の手前までにしました。全文が必要なら `modDetail` をオンにします。
- **通知の種類**：承認待ちとして扱うのを `permission_prompt` と `elicitation_dialog` に絞り、ログインの完了は送らず、知らない種類は「お知らせ」として送るようにしました。
- **README**：スマホから返事ができるのは、Remote Control を有効にしているときだけであることを書きました。
