# compact-memo 仕様書：圧縮前の退避メモ

## 目的

会話が長くなると、Claude Code は古い部分を要約して詰めます（圧縮）。このとき細かい決定事項が抜け落ちて、「さっき決めたことを忘れる」ことが起きます。

この mod は、圧縮の直前にいまの状況をメモにまとめ、圧縮後の会話の末尾にそのメモを足して Claude に渡し直します。

## 仕組み

`session.compact` イベントを1つ使います。このイベントは、圧縮が始まる直前に呼ばれます。手動の `/compact` でも、自動の圧縮でも同じです。

1. **圧縮前**：要約の担当（summarizer）への指示に、次の一文を足します。
   > ユーザーと合意した決定事項、却下した案とその理由、未解決の問題は、省略せず箇条書きで残すこと。

   `/compact 〇〇` のように手動で指示を付けた場合は、その指示のあとにつなげます。
2. **圧縮後**：要約済みの会話の末尾に、退避メモを1件足します。残すことが何もないときは足しません。
3. **知らせる**：メモを足したときは、トーストで「圧縮前のメモを渡し直しました」と知らせます。

決定事項は機械的には拾えないので、1 の指示で要約そのものに残させます。2 のメモは、機械的に確かめられる事実だけで作ります。どちらも圧縮の処理の中で行うので、追加の API 呼び出しは発生しません。

### 圧縮の種類による違い

| 種類（`trigger`） | 指示の追加 | メモの追加 |
| --- | --- | --- |
| `manual`（`/compact`） | する | する |
| `auto`（自動） | する | する |
| `plugin`（ほかの mod が圧縮した） | する | する |
| `precompute`（前もって要約だけ作っておく） | する（あとで使われる要約なので） | しない（実際に圧縮されるときに、最新の内容で足す） |
| サブエージェントの圧縮（`agentId` あり） | しない | しない |

`/clear` は圧縮ではなく会話を空にする操作なので、この mod は何もしません。

## 退避メモの中身（0.2）

メモの読み手は、圧縮後の Claude です。圧縮後に Claude が本当に困るのは「何を目指していて、次に何をするか」がわからなくなることです。ファイルの一覧やコマンドの結果は、Claude が自分で調べ直せます。そこで、メモには「調べ直せないこと」と「すぐ使える目印」だけを残します。

```
【圧縮前の退避メモ（compact-memo が自動で追加）】
claude-mods・10/24 21:05 の圧縮の直前の状況です。要約と食い違う場合は、このメモと実際のファイル・git を優先して確かめてください。変更中のファイルは git status で確かめてください。

## いまのゴール（goal2）
全テストが通ること

## やることリストの残り
▶ 取り組み中の項目
・未着手の項目

## いまのブランチ
fix-compact-memo-trim

## このセッションのコミット（新しい5件）
- 1a2b3c4 Add ...

## 気をつけること
- 最後に実行したテスト・チェックが失敗のままです
```

| 項目 | 取り方 | 取れないとき |
| --- | --- | --- |
| 見出しの2行目 | セッションを開いたフォルダの名前（`session.start` の `cwd`）と、圧縮した時刻 | フォルダ名を省く |
| いまのゴール | goal2 の状態（`goal2.goal`）の条件。一時停止中なら見出しにそう書く | 項目ごと省く |
| やることリストの残り | progress-panel の状態（`progress-panel.progress`）のうち、未完了のもの（30件まで） | 項目ごと省く |
| いまのブランチ | `git rev-parse --abbrev-ref HEAD` | 項目ごと省く（git が使えないフォルダなど） |
| このセッションのコミット | progress-panel の作業ログの、新しい5件 | 項目ごと省く |
| 気をつけること | progress-panel の作業ログで、いちばん最後のテスト・チェックが失敗だったときだけ1行 | 項目ごと省く |

- **残すことが何もないとき**（ゴール・やることの残り・コミット・失敗がどれもないとき）は、メモを足さず、トーストも出しません。ブランチ名だけのメモは役に立たないからです。
- goal2 や progress-panel が入っていなくても動きます。その場合は、ブランチ名だけになるので、上のとおりメモは足しません。
- メモ全体は 6,000 文字までにします。1行は 200 文字までにします。
- ほかの mod の状態は読むだけで、書き換えはしません。

### 0.1 から変えたこと（2026-10-24）

実際に保存された5件のメモを見直したところ、次のことがわかりました。

| 0.1 の項目 | 問題 | 0.2 での扱い |
| --- | --- | --- |
| 直近の依頼（最後の3件） | 「2」「入れてください」「はい、消してください」など、前後がないと意味のない短い返事ばかりだった。さらに、前回のメモそのものを「依頼」として拾うバグがあった（メモはユーザーの発言の形で会話に入るため） | やめる |
| 変更中のファイル（git status） | 別フォルダの画像の付属ファイル 80 件で 5,000 文字を使い切った例があった。Claude は自分で git status を実行できる | やめる。「git status で確かめて」と書くだけにする |
| 未解決の問題（失敗したコマンドの一覧） | 長いコマンドが途中で切れて並ぶだけで、テスト以外の失敗や、その後に直ったものも残っていた | 「最後のテスト・チェックが失敗のまま」の1行だけにする |
| やることリストの残り | 役に立っていた | 残す |
| このセッションのコミット | 目印として少し役に立っていた | 新しい5件だけ残す |

あわせて、圧縮の記録から、自動圧縮はコンテキストが 92〜97% のときに始まっていることがわかりました（8回分。100万トークン中 92万〜97万）。

## 保存と見返し

- **保存**：作ったメモは `$.store` に残します。セッションをまたいで、直近5件まで持ちます。
- **記録**：圧縮が起きた時刻、種類、そのときのコンテキスト使用率も一緒に記録します。直近20件まで持ちます。これは「実際に何%で自動圧縮されるか」を確かめるためのものです。
- **`/compact-memo`**：直近のメモと、圧縮の記録（種類と使用率）を出します。

## 対象外

- 決定事項を会話から機械的に取り出すこと（要約担当への指示で代わりにします）
- `/clear` のあとにメモを渡すこと

## テスト

`claude plugin test plugins/compact-memo` で、次の場合を確かめます。

- 手動・自動の圧縮で、指示が足され、メモが末尾に入り、トーストが出ること
- `/compact` に付けた指示が残ること
- `precompute` では指示だけを足し、サブエージェントの圧縮では何もしないこと
- メモの見出しにフォルダ名と時刻が入ること
- ゴール・やることの残り・ブランチ・コミット（新しい5件）・最後のテストの失敗が入ること
- 依頼の引用、git status の写し、失敗コマンドの羅列が入らないこと（前回のメモが会話にあっても拾わないこと）
- 最後のテストが成功なら「気をつけること」が出ないこと
- 残すことが何もないときは、メモもトーストも出ないこと
- `/compact-memo` で直近のメモと記録が見られること
